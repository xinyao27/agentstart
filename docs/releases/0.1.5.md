# AgentStart 0.1.5

- Runs local commands through the login shell's PATH. launchd, systemd, and the browser's
  native-messaging host start the daemon with a minimal PATH, so npx, gh, and CLIs installed by
  Homebrew or a shell rc were invisible to skills and preflight; the daemon now hydrates the login
  shell's PATH as the runtime comes up and resolves both `which` and local command spawns against
  it. Agent launches run through the same interactive-login startup files, so a detected agent
  starts instead of failing on a bare login shell.
- Accepts dropped images in a terminal. Dragging a screenshot or downloaded image onto a pane
  uploads it to the host that owns the terminal and pastes the returned temp path as a bracketed
  paste — the same contract clipboard screenshot paste already uses — so Claude Code, Codex, and
  OpenCode pick it up as an attachment. A drop that carries no image reports why instead of doing
  nothing.
- Keeps OpenCode scrolling after a pane reattach. OpenCode enables mouse reporting, but reopening
  the side panel or waking the machine replays its session into a fresh terminal and reset those
  mouse protocols whenever the pane did not read as a live agent: OpenCode's `OC | <task>` session
  title carries no status keyword, so every wheel notch fell back to an Up/Down key and cycled the
  prompt history instead of scrolling the conversation. A committed agent title and a foreground
  agent process now both count as a live pane, so its mouse modes survive the replay.
- Widens the terminal path. A rejected terminal input now names its reason — a locked writer is no
  longer reported as a renderer fault — and the input acknowledgement carries that code to the
  client. Under the hood one PTY read reaches the renderer as one 64 KiB frame, an agent-status
  hook burst folds into a single diff instead of one per event, and the runtime sender encodes each
  outgoing frame once instead of measuring and encoding it twice.
