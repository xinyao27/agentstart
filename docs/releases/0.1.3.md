# AgentStart 0.1.3

- Installs the browser extension from the release it just installed, instead of waiting on a store
  review. `agentstart install` stages the unpacked bundle by default, so the daemon and the
  extension you are running are always cut from the same commit. The Web Store listing is still
  there as an explicit channel for anyone who would rather let Chrome update the extension on its
  own.
- Keeps that staged copy current when you upgrade. `agentstart update` now syncs the extension to
  the version it is installing, and the running extension reloads itself at a quiet moment, so
  moving to a new release no longer needs a manual Reload on `chrome://extensions`. A directory with
  no extension manifest is left untouched, so a Web Store install does not quietly gain a second
  copy beside it.
- Survives an upgrade while a tab is still open. A pre-0.1.1 workbench still connected during the
  swap writes a retired `activeView` field, which made the daemon reject the whole settings write
  and turned the old bundle's unconsumed promise into an app-root error. Retired fields are now
  ignored on the write path exactly as they already were on the read path.
- Gives the one-command install a page of its own. `https://agentstart.ai/install` explains what the
  installer does, which environment variables it reads, and what to do afterwards, and the homepage
  now carries the same command in a box that shows the macOS/Linux command, the Windows command, or
  the channel links one at a time and copies exactly what is on screen. Both are in the prerendered
  HTML, so the copy that a search engine or a reader without JavaScript sees is the complete one.
- Makes the side panel's project controls work. Add Project, New workspace, the onboarding
  checklist, and Delete workspace did nothing when clicked in Chrome's side panel, because only a
  workbench tab mounts those dialogs and the side panel is a different document. They now open in a
  workbench tab — focusing the one you already have — and carry their selection with them, so
  deleting a workspace from the side panel still confirms on that workspace and a new workspace
  still starts on the project you picked.
