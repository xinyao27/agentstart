# AgentStart 0.1.2

- Installs the whole product with one command. `curl -fsSL https://agentstart.ai/install.sh | sh` on
  macOS and Linux, or `irm https://agentstart.ai/install.ps1 | iex` on Windows, installs the daemon,
  registers the browser connection, and hands over the mobile app — no package manager required
  first.
- Tells you when setup is actually finished. The installer opens the Chrome Web Store listing and
  then waits, reporting success once the extension has connected to the daemon rather than leaving
  an open store tab and no verdict.
- Answers whether the browser half is installed. `agentstart status` now reports the extension
  connection, which previously could not be observed from the daemon at all.
- Adds an install channel that does not go through the Web Store. With
  `AGENTSTART_EXTENSION_CHANNEL=unpacked` the daemon stages the extension on disk itself, verifying
  it against the release checksums, for machines that cannot use the store listing.
- Keeps that copy current across upgrades. The daemon refreshes the staged extension from the
  release it just updated to, and the running extension reloads itself at a quiet moment, so an
  upgrade no longer needs anyone to press Reload on `chrome://extensions`.
- Shows a scannable code for the iOS app during install, so pairing a phone starts from the same
  command as everything else.
- Points every mobile link — in the app, in the browser workbench, and on the website — at the
  TestFlight beta instead of the placeholder it showed before.
- Pins the extension to the published Chrome Web Store item. A store install and an unpacked install
  now share one extension ID, which is what lets the daemon recognize either one.
